# 디자인 평가 및 개선 계획

- **2026-07-29 업데이트: 개선 계획 D1~D8 전체 구현 완료.** 아래 발견 사항 14건 전부 코드 수정 + Playwright 재검증(데스크톱+모바일, 콘솔 에러 0건) 완료. 상세 구현 내용은 문서 하단 "구현 완료 기록" 섹션 참고. 이 문서는 평가 시점의 스냅샷으로 그대로 남겨두고, 실제 반영 상태는 하단 기록을 정본으로 볼 것.
- 평가일: 2026-07-29
- 평가 범위: v2 개편(Phase 0~7) 완료 직후의 전체 화면 — 홈, 새 프로젝트, 6단계 파이프라인(원고 변환/씬 분할/화면 설계/일관성 검수/이미지 생성/최종 뷰), 미리보기

- 이 문서는 평가 결과와 그에 따른 개선 계획만 담는다 — 실행은 각 항목을 `superpowers:brainstorming`/`writing-plans`로 넘길 때 별도로 진행한다(진행 방식은 [`docs/ROADMAP.md`](ROADMAP.md)의 "여러 개를 한 번에 묶지 말 것" 원칙을 따름).

## 총평

v2 개편은 기능적으로는 견고하다(Phase 0~7 전체가 실제 API로 E2E 검증됨). 하지만 이번 평가에서 **실제로 화면이 깨지는 버그 3건**을 발견했고, 이 중 하나(홈 화면 헤더 겹침)는 데스크톱에서도 나타나는 것이 아니라 모바일 전용이라 지금까지의 검증(주로 1280px 데스크톱 뷰포트로 진행됨)에서 놓쳤던 것으로 보인다. 그 외에는 "작동은 하지만 다듬어지지 않은" 수준의 일관성/정보위계 이슈가 여러 화면에 반복되는 패턴으로 나타난다.

## 발견 사항

심각도 기준: **P0(버그)** = 사용자가 실제로 화면이 깨진 것을 본다 / **P1(UX 결함)** = 깨지진 않지만 이해·조작이 어렵다 / **P2(다듬기)** = 일관성·마감도 문제, 기능에는 지장 없음.

### P0 — 실제로 깨지는 버그

1. **[모바일] AppShell 헤더에서 프로젝트 제목이 세로로 한 글자씩 줄바꿈됨**
   `app/AppShell.tsx:40` — 제목 `<Link>`에 `whitespace-nowrap`/`shrink-0`가 없어서, 좁은 화면에서 `flex` 컨테이너가 6개 단계 배지와 공간을 나누며 제목 블록을 극단적으로 축소시키고, 한글 텍스트가 공백 없이 글자 단위로 줄바꿈되어 헤더가 세로로 6줄 넘게 늘어난다(스크린샷: `03-markdown-mobile`, `05-screen-design-mobile`). 6단계 파이프라인 화면(원고 변환~최종 뷰) 전부에서 재현됨 — AppShell을 쓰는 모든 화면의 공통 결함.
   → 헤더 자체를 프로젝트 다루는 모든 세션에서 가장 먼저 보게 되는 요소인데, 모바일에서는 사실상 못 쓰는 수준.

2. **[모바일] 홈 화면에서 "새 프로젝트" 버튼이 제목과 겹침**
   `app/page.tsx` — 제목(`text-2xl font-bold`)과 버튼을 담은 컨테이너가 `flex items-center justify-between`만 쓰고 `flex-wrap`이 없어서, 좁은 화면에서 버튼이 제목 끝부분 위에 그대로 겹쳐진다(스크린샷: `01-home-mobile`).
   → 첫 화면부터 겹침이 보이면 신뢰도에 타격이 큼.

3. **[데스크톱+모바일] 미리보기 화면 하단 "이전 씬" 버튼이 사이드바에 가려짐**
   `app/projects/[projectId]/preview/PreviewViewer.tsx:57`(사이드바+본문을 담은 `flex max-w-[1400px]` 컨테이너)와 `:137`(푸터 내부의 독립적인 `mx-auto max-w-[1400px]`)이 서로 다른 기준으로 중앙 정렬됨 — 푸터는 사이드바(`w-56`, 224px)의 존재를 모른 채 전체 뷰포트 기준으로 중앙 정렬되므로, "이전 씬" 버튼이 사이드바 뒤로 밀려 들어가 가려진다(스크린샷: `09-preview-desktop` 좌측 하단).

### P1 — UX 결함

4. **[모바일] 미리보기에서 프로젝트로 돌아갈 방법이 없음**
   `PreviewViewer.tsx:58`의 `<aside>`가 `hidden md:block`이라 모바일에서는 사이드바 전체(씬 목차뿐 아니라 유일한 "← 프로젝트로 돌아가기" 링크도 포함)가 사라진다. 브라우저 뒤로가기 외에는 스토리보드/프로젝트로 돌아갈 UI가 없음.

5. **화면 설계(3단계) 카드가 8개 필드를 동일한 시각적 무게로 나열 — 정보 위계 없음**
   화면 유형/추천 레이아웃/근거(AI 산출) 와 화면 자막/키워드/이미지 설명/객체 배치/등장 순서/제작 지시(편집 대상)가 라벨 크기·색·간격이 전부 동일해서 어디가 핵심이고 어디가 부가 정보인지 구분이 안 됨(스크린샷: `05-screen-design-desktop`). 씬이 많아질수록(예: 20씬) 스크롤이 매우 길어짐.

6. **일관성 검수 이슈 카드가 내부 타입 슬러그를 그대로 노출**
   `duplicate-layout`(kebab-case), `missing_learning_objective`(snake_case)처럼 케이스 컨벤션조차 다른 개발자용 문자열이 그대로 사용자에게 보임. "warning" 배지도 번역 없이 영어 그대로 노출됨(스크린샷: `06-review-desktop`). `severity`별 색상 차별화도 약함(warning/error 모두 `secondary`/`destructive`뿐, amber 계열 같은 경고색 미사용).

7. **생성된 이미지에 높이 제한이 없어 카드가 매우 길어짐**
   `ImagesEditor.tsx:144`, `PreviewViewer.tsx:106` 둘 다 `w-full rounded border object-cover`만 쓰고 `h-*`/`aspect-*`가 없어 `object-cover`가 사실상 무의미함 — 1536×1024 원본 비율 그대로 전체 너비로 렌더링되어 카드가 세로로 매우 길어짐(스크린샷: `07-images-desktop`). 씬이 여러 개면 스크롤이 과도하게 길어짐.

8. **최종 스토리보드 뷰가 생성된 이미지를 전혀 보여주지 않음**
   Phase 7에서 이미지 생성 단계를 추가했는데, "최종 스토리보드"(`storyboard/page.tsx`)는 여전히 텍스트 요약만 보여주고 이미지 유무조차 표시하지 않는다. 실제 이미지를 보려면 "미리보기로 보기" 버튼을 눌러 별도 화면으로 가야 한다는 걸 사용자가 알아야 함 — "최종"이라는 이름과 실제 내용(텍스트만)이 불일치.

### P2 — 다듬기 / 일관성

9. **다크모드 CSS는 완성되어 있지만 진입 경로가 전혀 없음**
   `app/globals.css`에 `.dark` 클래스 기준 다크모드 변수가 전부 정의되어 있으나(Phase 2 때부터 존재), `.dark` 클래스를 `<html>`에 붙이는 코드도, 토글 UI도, `prefers-color-scheme` 연동도 전무함 — 죽은 코드 상태. 지금 상태로는 "다크모드가 있다"고 말할 수 없음.
10. **새 프로젝트 화면의 "타입" 필드가 스타일링되지 않은 네이티브 `<select>`**
    `app/projects/new/page.tsx` — `Input`/`Button`은 shadcn 컴포넌트를 쓰면서 이 필드만 브라우저 기본 select 스타일 그대로라 튐(스크린샷: `02-new-project-file-desktop`).
11. **2단계(씬 분할)가 shadcn `Textarea` 대신 순수 `<textarea>`를 사용**
    `SceneListEditor.tsx` — 다른 모든 멀티라인 입력(원고, 화면 설계)은 `Textarea` 컴포넌트를 쓰는데 이 화면만 수동으로 클래스를 복제한 raw `<textarea>`. 시각적으로 거의 동일해 보이지만 컴포넌트 일관성이 깨짐.
12. **콘텐츠가 짧은 단계에서 화면 하단에 큰 빈 공간**
    원고 변환/씬 분할 등 콘텐츠가 몇 줄만 있어도 페이지는 항상 최소 뷰포트 높이를 채우므로(`min-h-[calc(100vh-8rem)]`), 짧은 콘텐츠일 때 카드 아래로 수백 픽셀의 빈 여백이 남는다(스크린샷: `03-markdown-desktop`). 나쁜 건 아니지만 "화면을 다 채워야 완성돼 보인다"는 착시를 준다 — 우선순위 낮음.
13. **미리보기 TOC 활성 씬 강조가 스크롤 직후 한 박자 늦게 갱신됨**
    Phase 6 완료 시점에도 알려진 한계로 기록됨(`IntersectionObserver` 임계값 이슈). 기능은 정확히 동작하고 강조 타이밍만 부정확 — 재확인만 하고 우선순위는 낮게 유지.

### 별도 트랙 — 데이터 마이그레이션 결함 (디자인이 아니라 정합성 문제)

14. **Phase 5 이전에 만들어진 프로젝트가 홈 화면에서 상태 점 없이 깨져 보임**
    `테스트`(id `37fd903e-...`) 프로젝트의 `project.json`에 `currentStep: "visual-design"`이 저장돼 있는데, Phase 5에서 `PipelineStep` 유니온에서 `"visual-design"`/`"screen-types"`를 없애고 `"screen-design"`으로 통합하면서 `lib/projects/pipelineStatus.ts`의 `STATUS_BY_STEP`도 새 유니온만 다루도록 좁혔다. 디스크의 오래된 문자열은 여전히 `"visual-design"`이라 `STATUS_BY_STEP["visual-design"]`이 `undefined`가 되고, 홈 화면 카드에서 상태 점과 상태 라벨이 통째로 빈 값으로 렌더링된다(스크린샷: `01-home-desktop`, "테스트" 카드에 점이 없고 "· 생성일:"만 남음). 이 프로젝트로 아무 파이프라인 화면에 들어가면 AppShell의 6단계 배지 중 어느 것도 강조되지 않는 등 유사한 증상이 이어질 가능성이 높음(코드 확인은 안 했지만 같은 근본 원인).
    → 로컬 1인 도구라 실사용 영향은 제한적이지만, "단계 간 무효화 없음"이라는 v1 설계 원칙이 "파이프라인 자체를 재구성"하는 변경(Phase 5)까지는 커버하지 못한다는 것을 보여주는 구체적 사례. `getProjectStatus`에 알 수 없는 값에 대한 폴백을 넣는 것으로 화면 깨짐은 막을 수 있지만, 근본적으로는 "과거 데이터의 스키마 버전 관리를 어떻게 할 것인가"라는 더 큰 질문.

## 개선 계획

기존 v2 로드맵과 동일한 원칙(작고 독립적으로 검증 가능한 단위)을 따라 우선순위별로 쪼갠다. 지금 당장 실행하는 계획은 아니며, 착수 시 이 문서를 근거로 `writing-plans`로 넘길 것.

| Phase | 내용 | 포함 항목 | 근거 |
|---|---|---|---|
| D1 | 모바일 레이아웃 긴급 수정 | 1(헤더 줄바꿈), 2(홈 겹침), 3(미리보기 푸터 정렬), 4(미리보기 모바일 이탈 경로) | 전부 P0/P1이고 서로 다른 파일이라 독립적으로 고칠 수 있음. 사용자가 모바일에서 열어보면 바로 눈에 띄는 결함이라 가장 먼저. |
| D2 | 화면 설계 단계 정보 위계 재설계 | 5 | AI 산출(화면 유형/레이아웃/근거) 섹션과 편집 필드 섹션을 시각적으로 분리(예: 배경색 구분, 소제목, 또는 2단 그리드). 별도 브레인스토밍 필요 — 씬 20개 규모에서 실제로 스캔 가능한지 기준으로 설계. |
| D3 | 검수 이슈 표시 다듬기 | 6 | `type` 슬러그 → 사람이 읽는 한국어 라벨 매핑 테이블 추가(결정적 검사 3종은 이미 알려진 유한 집합이라 매핑 쉬움; AI가 생성하는 semantic 이슈의 `type`은 자유 텍스트라 별도 처리 필요 — 라벨 대신 아이콘+색상만 쓰는 방향도 검토). `severity`별 색상에 amber 계열 추가. |
| D4 | 이미지 표시 규격화 | 7, 8 | 이미지 카드에 `aspect-video`(또는 이미지 실제 비율인 1536:1024 ≈ 3:2) 고정 + `object-cover`로 실제 크롭 적용. 스토리보드 뷰에도 썸네일(있으면) 또는 "이미지 있음" 배지 추가 — 8은 사실상 "스토리보드에 이미지 열 추가"이므로 7과 같이 처리하는 게 자연스러움. |
| D5 | 다크모드 실제로 연결하기 | 9 | 최소한 헤더에 토글 버튼 추가 + `<html>`에 `.dark` 클래스 토글(로컬스토리지 저장) 정도의 작은 스코프로. `prefers-color-scheme` 자동 연동은 더 검토 필요(사용자가 명시적으로 원치 않을 수 있음 — 확인 필요). |
| D6 | 컴포넌트 일관성 정리 | 10, 11 | "타입" select → shadcn 사용 여부 결정(현재 `components/ui/`에 `Select`가 없음 — Phase 5 완료 노트에서 이미 "Select 추가 필요"로 언급됨, 화면 유형 드롭다운 전환과 같이 묶으면 `Select` 컴포넌트 추가가 한 번으로 끝남). raw `<textarea>` → `Textarea`로 교체(순수 리팩터링, 위험 낮음). |
| D7 | 데이터 마이그레이션 안전망 | 14 | `getProjectStatus`가 알 수 없는 `PipelineStep` 값에 폴백(`"not-started"` 등)을 반환하도록 방어 — 화면 깨짐은 즉시 막을 수 있는 1줄 수준 수정. 근본 대응(과거 `currentStep` 값을 어떻게 다룰지)은 별도 브레인스토밍 대상으로 남겨둠. |
