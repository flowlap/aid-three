# 이러닝 스토리보드 제작 지원 도구 — 설계 문서

- 작성일: 2026-07-27
- 상태: 승인됨 (v1 구현 대기)

## 배경 / 목적

이러닝 교육 과정 제작 과정에서 원고(또는 나레이션)를 영상 콘텐츠 제작용 스토리보드로 변환하는 작업을 지원하는 로컬 실행 웹앱이다. 원고 1개를 프로젝트 1개로 관리하며, 사용자가 각 단계의 AI 산출물을 검토·수정하면서 순차적으로 스토리보드를 완성한다.

## 범위 (v1)

**포함**
- 원고/나레이션 업로드(pdf, txt) → 마크다운 변환 → 씬 분할 → 화면 유형 선정 → 비주얼 설계 → 일관성 검수 → 최종 스토리보드 뷰

**제외 (향후 발전 단계)**
- pptx 템플릿 업로드 후 씬별 과정명/단원명/나레이션/설계 내용 자동 삽입 (내보내기)
- 씬별 AI 이미지 초안 생성 (OpenAI GPT Image 1.5 Low 사용 예정)

이 두 항목은 v1 아키텍처에서 자리는 마련하되 구현하지 않는다.

## 아키텍처 & 기술 스택

- **앱 형태**: Next.js(App Router) 단일 애플리케이션. `npm run dev`로 로컬 실행하며 Windows/Mac에서 브라우저로 접속하는 웹앱 형태.
- **UI**: React + TypeScript + shadcn/ui + Tailwind CSS
- **백엔드 로직**: Next.js API Route(Node.js)에서 PDF/TXT 파싱, 마크다운 변환, DeepSeek API 호출을 모두 처리. 별도 서버 프로세스 없음.
- **AI 제공자**: DeepSeek API (텍스트 분석 전 단계 공통 사용). 상세 내용은 [`docs/reference/deepseek-api.md`](../../reference/deepseek-api.md) 참고.
- **향후 이미지 생성**: OpenAI GPT Image 1.5 Low (v1 범위 아님, 인터페이스만 확장 가능하게 설계)

### 확장 포인트: Python 보조 프로세스 대비

처리 로직은 `lib/pipeline/*` 아래에 단계별 모듈로 분리하고, 각 모듈은 순수 함수형 인터페이스(`input → Promise<output>`)로 작성한다. 호출부는 해당 로직이 Node 내부 함수인지, child_process로 실행되는 외부 프로세스인지, 로컬 HTTP로 위임되는지 알 필요가 없도록 인터페이스만 바라본다. v1에서는 모든 모듈을 Node로 직접 구현하되, 이후 특정 모듈(예: PDF 파싱)을 Python 프로세스로 교체할 때 인터페이스 시그니처를 유지한 채 내부 구현만 교체할 수 있도록 한다. 지금 Python 코드는 작성하지 않는다.

## 데이터 모델 & 저장 구조

로컬 파일시스템에 프로젝트별 폴더로 저장한다. 프로젝트 목록 화면은 `data/projects/` 디렉터리를 스캔해서 구성한다.

```
data/projects/{project-id}/
  project.json         # 제목, 생성일, 현재 진행 단계(currentStep), 상태
  source/               # 업로드 원본 (pdf 또는 txt)
  narration.md          # 변환된 나레이션 마크다운 (원고형/나레이션형 공통 결과물)
  scenes.json           # 씬 분할 결과
  screen-types.json     # 씬별 화면 유형 선정 결과
  visual-design.json    # 씬별 비주얼 설계 결과
  review.json           # 일관성 검수 결과
```

- 각 단계 산출물은 별도 파일로 저장한다. 특정 단계만 재실행/재생성해도 이전 단계 파일은 그대로 유지된다.
- 사용자가 단계별 화면에서 내용을 수정하면 해당 JSON 파일을 바로 갱신한다. 버전 이력(undo/redo, 변경 이력)은 v1에서 관리하지 않는다.
- `project.json`의 `currentStep`으로 진행 상태를 추적해 프로젝트 목록에 표시한다.
- **가정**: 이전 단계를 나중에 수정해도 이후 단계 산출물을 자동으로 무효화하거나 재생성하지 않는다. 필요하면 사용자가 해당 단계에서 수동으로 재생성한다. (범위를 단순하게 유지하기 위한 v1 한정 결정)

## 파이프라인 단계 (입력 → 출력)

각 단계는 "AI 생성 → 화면에서 검토/수정 → 다음 단계" 패턴을 반복하는 선형 마법사(wizard)로 구현한다. 상세 입출력 스펙은 [`docs/reference/pipeline-steps.md`](../../reference/pipeline-steps.md)에 정리한다. 요약:

### 0단계 — 업로드
- pdf 또는 txt 업로드 + 원고/나레이션 타입을 사용자가 직접 선택 (자동판별 없음 — 오판 리스크 제거)

### 1단계 — 마크다운 변환
- 원고 타입: DeepSeek이 나레이션체 마크다운으로 변환
- 나레이션 타입: 내용은 그대로, 형태만 마크다운으로 정리
- 편집 가능한 마크다운 에디터로 검토/수정 → `narration.md`

### 2단계 — 씬 분할
- 입력: 나레이션, 씬 길이 기준 (일반 8~20초 / 강조 4~10초 / 표·그래프 15~30초 / 절차 애니메이션 15~40초)
- 분할 기준: 문장종결, 주제전환, 설명 대상 변경, 화면 유형 변경, 열거 시작/종료, 사례 또는 질문, 표·그래프 등장, 예상 재생시간
- 출력: 씬 목록, 각 씬 예상 재생시간, 분할 사유
- 원칙: 나레이션 문구는 임의 수정 없이 그대로 분절만 함. 원문과 씬 텍스트 합본이 달라지면 경고 표시(하드 블록 아님)
- 리스트 UI에서 씬 경계 조정(합치기/나누기)·시간 수정 가능 → `scenes.json`

### 3단계 — 화면 유형 선정
- 입력: 씬 나레이션, 앞뒤 씬 정보, 사용 가능한 화면 유형 목록
- 출력: 화면 유형, 추천 레이아웃, 추천 근거
- 씬별 드롭다운(화면 유형) + 텍스트(레이아웃) 수정 가능 → `screen-types.json`

### 4단계 — 비주얼 설계
- 입력: 씬 정보, 템플릿 정보, 디자인 가이드
- 출력: 화면 자막, 핵심 키워드, 이미지 또는 도식 설명, 객체 배치, 등장 순서, 제작 지시
- 전통적 스토리보드 형태(상단 화면 설계 영역 + 하단 나레이션)로 씬별 카드 편집 → `visual-design.json`
- 이미지 자체는 생성하지 않음 (텍스트 기반 설계서만 산출; 이미지 생성은 향후 단계)

### 5단계 — 일관성 검수
- 전체 씬 대상 자동 점검 항목: 용어 통일, 중복 화면 확인, 지나치게 긴 나레이션 확인, 동일 레이아웃 반복 확인, 나레이션-화면 불일치 확인, 학습 목표 누락 확인, 화면 번호·장 번호 확인
- 출력: 이슈 목록(심각도 + 해당 씬 id) → `review.json`
- 이슈 클릭 시 해당 씬의 4단계(비주얼 설계) 화면으로 이동해 즉시 수정 가능

### 6단계 — 최종 스토리보드 뷰
- 전체 씬을 스토리보드 문서 형태(화면 설계 + 하단 나레이션)로 읽기 전용 조회
- 향후 pptx 내보내기는 이 뷰의 데이터를 기반으로 구현 예정

## 프로젝트 관리

- 홈 화면: `data/projects/` 스캔 → 프로젝트 목록(제목, 생성일, 현재 단계) 표시
- 새 프로젝트 생성(업로드로 시작), 프로젝트 삭제(폴더 삭제) 지원

## 에러 처리

- DeepSeek API 호출 실패/타임아웃: 재시도 버튼 제공, 실패 사유 표시. 자동 재시도는 최소한으로(무한 재시도 금지)
- PDF/TXT 파싱 실패(손상 파일, 미지원 형식): 업로드 단계에서 즉시 에러 메시지
- 씬 분할 시 "원문 그대로 분절" 원칙 검증: 원본과 다르면 경고(하드 블록 아님, 최종 판단은 사용자)

## 테스트 전략

- 결정적 로직(폴더 CRUD, 마크다운 포맷팅, 씬 텍스트 무결성 검증, 일관성 검수 규칙)은 유닛 테스트로 커버
- DeepSeek 클라이언트는 인터페이스로 분리해 목(mock) 응답으로 단계별 UI/저장 로직을 테스트
- AI 산출물의 "품질"은 자동 테스트 대상이 아니며 사람이 각 단계에서 검토

## 향후 발전 (v1 범위 밖, 설계만 고려)

1. pptx 템플릿 업로드 → 씬별 과정명/단원명/나레이션/설계 내용 자동 삽입
2. 씬별 AI 이미지 초안 생성 (OpenAI GPT Image 1.5 Low)
