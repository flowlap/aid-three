# 화면 유형(Screen Type) 레퍼런스

이 문서는 화면 설계 단계(`lib/pipeline/selectScreenTypes.ts`, `lib/visual-templates/index.ts`)가 각 씬에 부여하는 화면 유형의 설계 방향과 유형별 상세 가이드를 정리한다. 코드를 수정할 때는 `lib/visual-templates/index.ts`의 `SCREEN_TYPE_OPTIONS`/`SCREEN_TYPE_INFO`가 실제 소스이며, 이 문서는 그 내용을 사람이 읽기 좋게 풀어 쓴 것이다 — 둘이 어긋나지 않도록 유형을 추가/변경할 때는 항상 두 곳을 함께 갱신한다.

## 설계 방향

1. **하나의 원천에서 AI 프롬프트와 사람용 문서를 동시에 생성한다.** `SCREEN_TYPE_INFO`(코드)가 각 유형의 짧은 설명을 담고 있고, `selectScreenTypes`는 이 설명을 그대로 프롬프트에 포함시킨다. 예전에는 화면 유형 이름만 나열했는데, 이름만으로는 AI가 비슷한 유형(예: 간지/타이틀형 vs 요약/정리형)을 헷갈리기 쉬웠다 — 설명을 붙이자 오분류가 줄었다.
2. **세 갈래 관례를 섞었다.** 화면 유형 14종은 한 가지 전통에서만 온 것이 아니라, 실제 영상/이러닝 제작 현장에서 쓰이는 세 갈래 관례를 조합했다:
   - **교수설계(Instructional Design) 관례** — 체크리스트형, 절차 애니메이션형, 요약/정리형, 용어 정의형, 질문/퀴즈형: 학습 목표 달성을 위해 정보를 구조화하는 방식.
   - **방송/모션그래픽 관례** — 간지/타이틀형(챕터 카드), 인용/사례형(로워써드 스타일 인용구), 타임라인형: 방송 편집에서 흔히 쓰는 전환/강조 장치.
   - **인터랙티브 러닝 관례** — 질문/퀴즈형: 학습자의 참여를 유도하는 패턴.
3. **문서 전체 맥락 + 직전 이력을 함께 준다.** 씬 하나만 보고 판단하면 앞뒤 씬 정보만으로는 부족한 경우(문서 도입부/말미)가 있어 `document-summary.txt`(문서 전체 3~5문장 요약)를 모든 프롬프트에 공통 컨텍스트로 포함한다. 또한 직전 1~2개 씬의 화면 유형을 프롬프트에 넣어 같은 유형이 3연속 반복되지 않도록 유도한다(2연속 시 해당 유형을 명시적으로 배제).
4. **caption/keywords는 AI가 전체를 읽고 새로 판단한다.** 화면 자막(`caption`)과 핵심 키워드(`keywords`)는 나레이션 앞부분을 잘라내거나(구 버전 `truncate()`) 등장 순서로 단어를 줍는(구 버전 `extractKeywords()`) 방식이 아니라, AI가 씬 나레이션 **전체**를 읽고 중요도 기준으로 직접 작성/선정한다. 로컬 휴리스틱은 AI 응답이 없을 때만 쓰이는 폴백으로 남아 있다.
5. **반복되기 쉬운 유형은 목업 레이아웃을 순환시킨다.** 간지/타이틀형과 텍스트 강조형은 한 프로젝트 안에서 여러 번 등장하기 쉬운데, 매번 똑같은 박스로 보이면 단조롭다. `computeMockupVariantIndexes`가 "이 화면 유형이 지금까지 몇 번째로 등장했는지" 세어 `ScreenMockup`이 2~3가지 레이아웃을 순환하며 보여주므로, 같은 유형이 연달아 나와도 다른 구성으로 보인다.

## 화면 유형 상세

### 간지/타이틀형
챕터/섹션 제목만 담은 순수 구분 화면(방송 편집에서 말하는 "간지"). 나레이션이 "학습 개요", "헤드라인"처럼 부연 설명 없이 제목/구획명뿐일 때 선택한다.
- **혼동 주의**: 요약/정리형(실제 내용 리캡)이나 텍스트 강조형(내용이 있는 강조 문구)과 다르다 — 이 유형은 내용이 아니라 표지 역할만 한다.
- **레이아웃**: 화면 중앙에 제목, 위아래 얇은 구분선. 목업 베리에이션 3종(중앙 정렬+구분선 / 좌측 컬러바+좌측정렬 / 전체 배경색 채움) 순환.

### 텍스트 강조형
핵심 문구·개념 하나를 화면 전체에 크게 강조. 짧고 임팩트 있는 한 문장을 전달할 때.
- **레이아웃**: 중앙 정렬 큰 타이포그래피. 목업 베리에이션 3종(중앙+아이콘뱃지 / 좌측 컬러바 / 아이콘+텍스트 칩) 순환.

### 인물 등장형
강사 또는 캐릭터가 등장해 설명하는 구도. 도입부, 친근한 전환, 사람 중심 설명에.
- **레이아웃**: 인물은 화면 좌/우 1/3 지점, 텍스트는 반대쪽.

### 이미지 설명형
단일 이미지와 캡션으로 나레이션이 가리키는 구체적 대상을 시각화. 이 앱의 기본/폴백 유형이기도 하다(인식 못 하는 유형이 오면 이 템플릿으로 대체).
- **레이아웃**: 이미지 중앙, 캡션 하단.

### 표/그래프형
수치 데이터 비교. 통계, 수량, 추이 등 숫자가 중심일 때.
- **레이아웃**: 막대/그래프 중앙, 제목 상단, 축 라인 + 항목 라벨(있는 경우 키워드를 라벨로 사용).

### 인포그래픽형
개념 간 관계·구조를 나타내는 다이어그램(허브-스포크, 계층 구조, 분류 트리 등).
- **혼동 주의**: 순서가 있는 절차(절차 애니메이션형)나 수치 비교(표/그래프형)가 아니라, "무엇이 무엇과 어떻게 연결/포함되는지" 관계를 설명할 때 고른다.
- **레이아웃**: 중심 개념이 화면 중앙, 관련 개념이 주위에 방사형 배치.

### 절차 애니메이션형
순차적 단계나 프로세스. "먼저 ~하고 그다음 ~한다"처럼 순서가 있는 설명에.
- **레이아웃**: 좌→우 또는 위→아래 순차 배치, 단계별 번호.

### 비교 대조형
두 대상을 좌우로 나눠 대비. "A와 B의 차이"를 설명할 때.
- **레이아웃**: 좌/우 2분할 + 중앙 구분선/VS 표시, 각 측 상단에 라벨(키워드 우선 사용).

### 타임라인형
시간 순서에 따른 사건·변화 나열. 연혁, 히스토리, 발전 과정에.
- **레이아웃**: 가로 타임라인 + 시점별 포인트 라벨.

### 용어 정의형
특정 용어나 개념을 소개하고 뜻을 설명하는 사전식 카드. "~란 무엇인가", "~는 ~를 뜻한다"처럼 용어 정의가 나레이션의 핵심일 때.
- **레이아웃**: 용어는 상단에 크게(첫 키워드 사용), 정의 문장은 그 아래.

### 질문/퀴즈형
학습자에게 질문을 던지거나 간단한 퀴즈/자가 점검을 제시하는 화면. 나레이션이 반문형 질문이거나 학습자의 참여·생각을 유도할 때.
- **레이아웃**: 질문 문구 중앙, 물음표 아이콘. 정답은 다음 화면에서 공개하는 것을 전제로 한다.

### 인용/사례형
인용구 또는 실제 사례를 카드형으로 강조. 발화 인용, 케이스 스터디에.
- **레이아웃**: 인용구 중앙 + 따옴표 장식, 출처는 하단 소형 텍스트.

### 체크리스트형
항목을 목록으로 나열. 준수사항, 준비물, 요건 목록에.
- **레이아웃**: 좌측 정렬 리스트, 항목 앞 체크 아이콘.

### 요약/정리형
챕터·섹션을 마무리하며 핵심 포인트를 정리. 앞서 다룬 내용의 리캡에.
- **혼동 주의**: 간지/타이틀형과 달리 실제 내용 요약(키워드 목록)을 담는다.
- **레이아웃**: 제목 + 핵심 포인트 목록(키워드 우선 사용).

## 새 유형을 추가하려면

1. `lib/visual-templates/index.ts`의 `SCREEN_TYPE_OPTIONS`에 이름 추가, `SCREEN_TYPE_INFO`에 설명 작성 (AI가 다른 유형과 헷갈리지 않도록 "무엇과 다른지"를 명시).
2. 같은 파일 `TEMPLATE_BODIES`에 해당 유형의 로컬 템플릿(설명/배치/등장순서/제작노트) 추가.
3. `components/ScreenMockup.tsx`에 목업 렌더링 케이스 추가 (아이콘은 `TYPE_ICONS`에 등록).
4. 반복이 잦을 것으로 예상되면 `MOCKUP_VARIANT_COUNTS`에 등록해 레이아웃 순환을 켠다.
5. 이 문서에 상세 설명 섹션 추가.
6. `lib/visual-templates/index.test.ts`에서 새 유형도 `computeVisualDesign`이 정상 동작하는지 커버되는지 확인 (`SCREEN_TYPE_OPTIONS` 전체를 순회하는 테스트가 이미 있어 대부분 자동으로 커버된다).
